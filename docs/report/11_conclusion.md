# 제 11 장  결론 및 향후 개선

---

## 11.1 결과 요약

본 졸업 작품은 다음 결과물을 산출했다.

### 11.1.1 하드웨어

- **양방향 차압식 호흡근 훈련 디바이스 시제품** — ESP32-S3 + MPXV7007DP + LiPo 400 mAh + DRV2605L 햅틱 + 1.9" IPS LCD.
- **3 단계 오리피스 디스크** (4 / 3 / 2 mm) 로 기계적 강도 1 차 조절.
- **외부 전원 버튼** (PB61412L) + 3 초 wake gate 로 의도하지 않은 ON 방지.

### 11.1.2 펌웨어

- **6-state machine + 4-phase Turn cycle** — Boot/Standby/Prep/Train/Rest/Summary, 호기/흡기/휴식 cycle 자동 진행.
- **양방향 측정 + 비대칭 zone hit** — 호기 turn 에서 양압, 흡기 turn 에서 |음압| 만 평가.
- **%PImax 기반 적응형 목표 압력** — 강도 단일 변수로 흡기/호기 4 개 target 자동 계산 + 안전 상한 자동 clamp.
- **Cycle offset** — 측정 화면이 흡기 / 호기를 자유 선택 가능.
- **Deep sleep 10 μA** — 400 mAh 배터리로 5 년+ 보관 가능.

### 11.1.3 BLE 프로토콜

- **GATT 5 char + 6 opcode** — 100 Hz 압력 stream, 세션 명령, 통계 요약, 디바이스 상태, 이력.
- **v4.1 length-prefix 호환 확장** — `START_SESSION` 의 `startPhase` byte, `SET_TARGET` 의 5 B clinical payload.

### 11.1.4 앱

- **21 화면** — 첫 실행 / 메인 셸 4 탭 / 보조 / 동반자.
- **PImax / MEP 측정 화면 (v4.1 신규)** — 호기 → 흡기 순차, 디바이스와 동기.
- **BreLow 진화 캐릭터** — 3 단계 Rive (Egg → Baby → Oxygen), 게이미피케이션.
- **동반자 모드** — Firebase 익명 인증 + 6 자리 코드 + 세션 백필 + 응원 알림.
- **Samsung Health 연동** — 수면 / SpO₂ / 무호흡 징후 동기화, 훈련 전후 비교.

### 11.1.5 임상 근거 기반 설계

기존 상용 디바이스 대비 차별점:

| 항목 | 시중 일반 | BRELOW |
|---|---|---|
| 강도 단위 | 절댓값 (예: 20 cmH₂O) | **% PImax / % MEP** (개인 적응형) |
| 단계 | 다이얼 1~10 (기계적) | **3 단계** (Beginner / Normal / Advanced, 임상 근거) |
| 양방향 측정 | 호기 또는 흡기 중 1 | **양방향 동시** (IMT + EMT) |
| 데이터 | 디바이스에만 표시 | **앱 영속 + 추이 + 코칭 + 동반자 공유** |
| 측정 표준 | 없음 | **Vranish 2016 / Black & Hyatt 1969 / POWERbreathe / Bissett 2019 / The Breather 참조** |

## 11.4 향후 개선

### 11.4.1 단기 (6 개월 이내)

1. **PImax 자동 추적** — §6.6 참조. 매 세션 maxPressure 의 7 일 95 퍼센타일로 PImax 추정 갱신.
2. **자동 강도 상향** — hit_percent ≥ 80 % 가 일정 기간 지속되면 다음 단계 제안.
3. **iOS 빌드** — flutter_blue_plus 가 iOS 지원, 권한 / Info.plist 만 추가 작업.
4. **사용자 알림** — 매일 정해진 시간에 훈련 알림 (`flutter_local_notifications` 활용, 채널 이미 구축).
5. **임상 표준 측정 모드** — PImax / MEP 측정을 1 초 sustained / sitting position 안내와 함께 임상 표준 모드로.

### 11.4.2 중기 (1 년)

6. **iOS 정식 출시** — 앱스토어 등록 + Foreground service 대체 (iOS 는 background BLE 별도 처리).
7. **의료기기 등급 검토** — 본 디바이스를 의료기기 등급 1 (의료기기 인허가 또는 신고) 으로 분류할지 식약처 사전 상담.
8. **OTA 펌웨어 업데이트** — BLE 또는 WiFi (ESP32-S3 의 WiFi 도 활성화) 를 통한 펌웨어 업데이트.
9. **챌린지 기능** — 디바이스 사용자 + 동반자가 함께하는 30 일 챌린지.

### 11.4.3 장기 (2 년+)

10. **다중 동반자 연결** — 가족 여러 명을 동시 연결.
11. **임상 시험** — 수면무호흡 환자 N 명 대상 6 주 IMT 효과 측정 (Vranish 2016 재현).
12. **데이터 분석 — 의사용 대시보드** — 환자별 추이 그래프 + 처방 강도 조정.
13. **헬스케어 플랫폼 연동** — Apple Health, Google Fit, 의료 EHR (FHIR).

## 11.5 본 작품의 의의

BRELOW 는 단순한 호흡 훈련 기기가 아니다. 본 작품은 다음 세 가지 의의를 가진다.

### 11.5.1 학술적 의의

기존 시중 디바이스가 절댓값 강도를 사용하는 데 반해, BRELOW 는 **%PImax 기반 적응형 강도** 를 일반 소비자 디바이스에 적용했다. 이는 임상 문헌 (Vranish 2016, Bissett 2019, POWERbreathe) 의 권장 사항을 충실히 구현한 사례이다.

### 11.5.2 산업 디자인 의의

호흡 훈련은 매일 5 분의 단순 반복 활동이지만 **꾸준한 동기 부여가 가장 어려운 challenge** 이다. BRELOW 는 이를 3 가지 layer 로 해결했다 — (1) 자체 게이미피케이션 (BreLow 캐릭터), (2) 데이터 시각화 (홈/추이/마일스톤), (3) **사회적 동기 부여 (동반자 모드)**. 특히 동반자 모드의 익명 인증 + 6 자리 코드 페어링은 회원가입 부담 없이 가족 응원을 즉시 활성화할 수 있다.

### 11.5.3 공학적 의의

ESP32-S3 + Flutter + Firebase + Drift + Samsung Health 의 5 영속 계층을 SSOT 원칙으로 일관되게 설계했다. BLE 프로토콜은 length-prefix 호환 확장(v4.0 ↔ v4.1) 으로 진화하면서도 구버전과의 호환을 유지했고, 펌웨어와 앱 모두 모듈 책임을 명확히 분리해 유지보수성을 확보했다.

## 11.6 마치며

본 졸업 작품은 한남대학교 디자인팩토리 CPD 의 컴공·시각디자인·기계공 협업의 결과물이다. 임상 근거를 산업 디자인에 충실히 반영하면서도, 사용자 경험을 단순하고 게이미피케이션 친화적으로 풀어낸 점에 자부심을 가진다.

호흡근 훈련은 비록 작은 활동이지만, 수면의 질과 일상의 삶에 큰 영향을 준다. BRELOW 가 더 많은 사용자의 더 깊은 잠을 응원할 수 있기를 기대한다.

> "매일 5 분, 더 깊은 숨, 더 깊은 잠." — BRELOW 슬로건
